# 適合検査の標本（probe）

正典 AIPL が三台の実機とホスト VM で**同じように**動くかを測るための標本。
すべて正典の型検査（`./tools/tc`）を通してある。

    ./tools/board_matrix.sh [pi3|pi4|pi5|mac|all]

`expect/*.txt` は**ホスト VM の出力から起こす**。正典の参照実装が基準で、
実機がそれに合わせる ―― 逆にしてはいけない。実機の癖を期待値に書き込むと、
その癖が仕様に昇格してしまう。

| 標本 | 見るもの |
|---|---|
| `p1_basic`   | class / method / var / フィールド / new / init / send / send! / print / 文字列 / `++` |
| `p2_now`     | now / future / await / 期限 / `result` / `is_ok` / `value` |
| `p3_select`  | select / case / timeout |
| `p4_bool`    | 真偽値と比較（`var` で始まるので、板の「AIPL 判定」も試す） |
| `p5_effects` | 型・効果・レベルの注釈（板は受理して捨てる。検査は正典側） |
| `p6_num`     | `float` / 配列 / 数学組込み |
| `p7_reply`   | `replyto` / `answer` / 引数型 `reply` / `acquire` / `release` |
| `p8_named`   | `spawn` / `web_expose`（名前つきアクター） |
| `p9_wait`    | `wait` |

`remote` は二台以上が同時に生きていないと測れないので、この一式には入れていない
（引き継ぎメモの総当たり表を見よ）。

## 掘り当てたもの（この一式を作った日に）

- `var` で始まる正典プログラムが板で C 扱いになり `cc: expected type` で落ちた。
  板は「最初の語が `class`」でしか AIPL と見なしていなかった。Pi 3 だけ通ったのは
  前段が Mac 側にあって判定が要らないため ―― **機内前段を持つ板だけの問題**だと、
  検査の表がそのまま示した。
- 実数の表示が切り捨てで、参照実装（四捨五入）と 1 桁ずれた（`2.718281` / `2.718282`）。
  個別に測っていたときは、どちらが正しいのか判断する基準が無かった。

どちらも「三台を並べて、参照実装と突き合わせる」形にして初めて見えた。
