\begin{abstract}
本書は AIPL（ABCL$^{c}$+）の\textbf{現状の}ユーザーズガイドである。
第 \ref{part:start} 部で言語の全体像と最短の動かし方、
第 \ref{part:lang} 部で文法と型システムの仕様、
第 \ref{part:sample} 部でサンプルプログラムをソースと実行結果つきで、
第 \ref{part:tool} 部でビルド・実行・検査の道具立てを、
第 \ref{part:appendix} 部に文法の要約・現状の限界・旧版からの移行を置く。

AIPL は\textbf{アクター}を単位とする並行言語で、値は \texttt{return} ではなく
\texttt{reply} で返す。その上に三つの静的な仕組みが載っている。
\textbf{型}（\texttt{reply} から戻り値型を推論し、注釈も書ける）、
\textbf{効果}（\texttt{!\{ai, net\}} のようにメソッドが世界に及ぼす作用を宣言する）、
\textbf{期限}（\texttt{now ... timeout ... else ...} で待ちに上限を置く）。
この三つは互いに噛み合っていて、たとえば
「実時間で動くアクターが、機外のモデルを同期で呼ぶ」ことが
効果検査だけで禁止できる。

本書は前版（対象コミット \texttt{04892cf}）を全面的に書き直したものである。
前版以降に効果注釈・期限付きの待ち・等値比較・単項マイナス・真偽値リテラルが
入り、「既知の欠落」として挙げていた項目のいくつかが解消した。
差分だけを知りたい場合は \S\ref{sec:migrate} を見ればよい。
\end{abstract}

\section{AIPL とは}

AIPL は ABCL/1 の系譜にあるアクター言語である。プログラムは
\textbf{クラス宣言}と\textbf{グローバル文}の並びで、クラスから生成された
アクターがメッセージを送り合って動く。

\begin{lstlisting}
class Counter {
  var n = 0;                       // フィールド（アクターの状態）
  method bump() : int !{mut} {     // 戻り値型 int、効果は mut
    n = n + 1;
    reply(n);                      // 呼び出し側へ値を返す
  }
}

var c = new Counter();             // アクターを1台つくる
print(now c.bump() timeout 100 else 0);
\end{lstlisting}

他の言語との違いのうち、最初に押さえるべきものは四つある。

\begin{enumerate}
\item \textbf{アクターは 1 台 1 スレッド}で、受け取ったメッセージを
  逐次に処理する。フィールドへの同時アクセスは起こらない。
\item \textbf{値は \texttt{reply} で返す。} \texttt{return} は無い。
  \texttt{reply} は呼び出し側の future を解決する操作で、
  メソッドの実行はその後も続けられる。
\item \textbf{送信には三種類ある。} \texttt{send}（待たない・文）、
  \texttt{now}（返信まで待つ・式）、\texttt{future}（待たずに引換券を得る・式）。
\item \textbf{待つと固まる。} \texttt{now} で待っている間、そのアクターは
  他のメッセージを一切処理できない。だから待ちには期限を書く。
\end{enumerate}

\section{三つの静的な仕組み}

\subsection{型 --- 何を返すか}

メソッドの戻り値型は本体の \texttt{reply} から推論される。
省略可能な注釈 \texttt{method m(x) : T} も書ける。
注釈を書くと、全実行パスで \texttt{reply} することが検査され、
かつ宣言した型が\emph{期待型}として式の推論に流れる。

\subsection{効果 --- 世界に何をするか}

メソッドが持つ作用を \eff{...} で宣言する。効果は 8 種類ある
（\S\ref{sec:effects}）。省略すると本体から推論され、
書けば「本体の効果 $\subseteq$ 宣言した効果」が検査される。

\begin{lstlisting}
method plan(goal) : string !{ai, net} { reply(ai_call("plan: " ++ goal)); }
method peek()     : int    !{}        { reply(n); }
\end{lstlisting}

\texttt{ai} と \texttt{net} を分けてあるのが要点で、
「AI を使うが機外へは出ない」オンデバイス推論を \eff{ai} だけで表せる。

\subsection{期限 --- いつまで待つか}

\begin{lstlisting}
var r = now planner.plan(g) timeout 2000 else "(timed out)";
\end{lstlisting}

期限内に返信が来なければ \texttt{else} 節の値になる。
期限付きの待ちだけを使うプログラムでは\textbf{デッドロック自由}が定理として言える
（\texttt{docs/aipl\_soundness2\_ja.pdf}。本書 \S\ref{sec:soundness} に要約）。

\part{言語ガイド}
\label{part:lang}

\section{プログラムの構成}

プログラムは\textbf{宣言の並び}である。宣言は次のいずれかで、
順序は自由だが、参照する名前は実行時に解決される。

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
宣言 & 内容 \\
\midrule
\texttt{class C \{ ... \}}            & クラス定義 \\
\texttt{var x = e;}                   & グローバル変数 \\
\texttt{var x = new C(args);}         & アクターの生成 \\
\texttt{send t.m(args);}              & グローバルな非同期送信 \\
\texttt{send! t.m(args);}             & 同上（検査を緩めた送信） \\
\texttt{f(args);}                     & 組込み関数の呼び出し \\
\bottomrule
\end{tabular}
\end{center}

\begin{quote}\small
グローバルの位置に \texttt{if} や \texttt{while} は書けない。
制御構造が必要ならメソッドの中に置いて \texttt{send} で起動する。
\end{quote}

クラスは\textbf{フィールドの並び}に\textbf{メソッドの並び}が続く形である。

\begin{lstlisting}
class Counter {
  var n = 0;                    // フィールドは先。var か float で宣言する
  float ratio = 1.5;
  method init(start) {          // init は new のときに自動で呼ばれる
    n = start;
  }
  method bump() : int !{mut} {
    n = n + 1;
    reply(n);
  }
}
\end{lstlisting}

\begin{itemize}
\item フィールドはメソッドより\textbf{前}に書く。
\item クラスには\textbf{メソッドが最低 1 つ}必要である（文法上、
  フィールドだけのクラスは書けない）。
\item \texttt{init} という名前のメソッドは \texttt{new C(args)} のときに
  自動で呼ばれる。引数の個数が合わないと生成が飛ばされ、
  \texttt{[Actor] x: no init; skipped} と表示される。
\item フィールドの初期化式で型が決まる。\texttt{var n = 0;} は \ty{int} に
  なるので、あとから \ty{float} や文字列を代入すると型エラーになる。
\end{itemize}

\section{型}

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
型 & 説明 \\
\midrule
\ty{int}, \ty{float}, \ty{string}, \ty{bool}, \ty{unit} & 基底型 \\
\ty{T[]}          & 配列（\texttt{array\_*} 組込みで扱う） \\
\ty{future\ T}    & \texttt{future} 送信の結果。\texttt{await} で \ty{T} を取り出す \\
\ty{actor(C)}     & クラス \texttt{C} のアクター。\texttt{new C(...)} の型 \\
\ty{any}          & 静的に内容を保証しない境界（\texttt{sender}、リモート送信先） \\
\bottomrule
\end{tabular}
\end{center}

戻り値型注釈に書けるのは
\texttt{int} / \texttt{float} / \texttt{string} / \texttt{bool} /
\texttt{unit} / \texttt{any} と、大文字で始まるクラス名（アクター型）である。
小文字で始まる未知の名前は
\texttt{unknown type name in return annotation} として構文エラーになる。

\begin{quote}\small
\textbf{メソッドの引数は単相である。} シグネチャの引数型変数は
全呼び出し地点で共有されるので、同じメソッドを \ty{int} と \ty{string} で
呼ぶと衝突する。多相なメソッドは書けない。
\end{quote}

\begin{quote}\small
\ty{int} と \ty{float} の間に\textbf{暗黙変換は無い}。
\texttt{var h = new Hello(5);} が \texttt{float} のフィールドに繋がると
型エラーになるので、\texttt{new Hello(5.)} と書く。
\end{quote}

\section{式}

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
式 & 意味 \\
\midrule
\texttt{123}, \texttt{1.5}, \texttt{"abc"}, \texttt{true}, \texttt{false} & リテラル \\
\texttt{x} & 変数・フィールド・仮引数 \\
\texttt{-\,e} & 単項マイナス。\texttt{neg(e)} へ落ちる。\ty{int}/\ty{float} \\
\texttt{a ++ b} & 文字列連結（両辺を文字列化）\\
\texttt{a + b}, \texttt{a - b}, \texttt{a * b} & 数値演算。\ty{int} 同士は \ty{int}、
  \ty{float} 同士は \ty{float} \\
\texttt{a / b} & 除算。\ty{int} 同士でも \ty{float}（整数除算はしない） \\
\texttt{a == b}, \texttt{a != b} & 等値・非等値。\ty{int}/\ty{float}/\ty{string}/\ty{bool} \\
\texttt{a > b}, \texttt{a < b}, \texttt{a >= b}, \texttt{a <= b} & 比較。結果は \ty{bool} \\
\texttt{new C(args)} & アクターの生成（効果 \eff{mem}） \\
\texttt{now t.m(args)} & 同期送信。返信が来るまで待ち、その値になる \\
\texttt{now t.m(args) timeout $n$ else $e$} & 期限付きの同期送信 \\
\texttt{future t.m(args)} & 非同期送信。\ty{future\ T} を返す \\
\texttt{await e} & future の解決を待つ \\
\texttt{await e timeout $n$ else $e'$} & 期限付きの \texttt{await} \\
\texttt{f(args)} & 組込み関数の呼び出し \\
\texttt{( e )} & 括弧 \\
\bottomrule
\end{tabular}
\end{center}

送信先 \texttt{t} は\textbf{アクター参照が入った変数名}か
\texttt{remote("host:port", "actorName")} である。クラス名ではない。

\subsection{優先順位}

弱い順に

\begin{center}
等値 \texttt{==} \texttt{!=} \ $<$\ 比較 \texttt{>} \texttt{<} \texttt{>=} \texttt{<=}
\ $<$\ 連結 \texttt{++} \ $<$\ 加減 \texttt{+} \texttt{-}
\ $<$\ 乗除 \texttt{*} \texttt{/} \ $<$\ 単項マイナス
\end{center}

である。したがって \texttt{1 + 2 == 3} は \texttt{(1 + 2) == 3}、
\texttt{"x=" ++ a + b} は \texttt{"x=" ++ (a + b)} と読まれる。
二項演算子は\textbf{すべて左結合}である（等値も含む）---- \texttt{1 == 2 == false} は \texttt{((1 == 2) == false)} と読まれて \texttt{true} になる。単項マイナスは前置なので重ねられる（\texttt{- - 3} は \texttt{3}）。

\subsection{\texttt{+} と \texttt{++} を混同しない}

\texttt{+} は\textbf{数値専用}である。文字列を混ぜると
\texttt{no overload of + matches (string, int)} になる。

\begin{lstlisting}
print("count = " ++ n);      // 正しい
print("count = " + n);       // 型エラー
\end{lstlisting}

\texttt{++} は両辺を文字列化してから連結するので、どちらが文字列でなくてもよい。

\subsection{曖昧なオーバーロード}

両辺が未束縛の \texttt{a + b} は \ty{int} とも \ty{float} とも解釈でき、
principal type を持たない。これはエラーである。注釈を書けば
期待型が式へ流れて一意に決まる。

\begin{lstlisting}
method add(a, b)       { reply(a + b); }   // エラー: ambiguous overload
method add(a, b) : int { reply(a + b); }   // 注釈で確定する
\end{lstlisting}

\texttt{AIOS\_LAX\_OVERLOAD=1} で従来の「警告して既定候補を選ぶ」動作に戻せる。
等値 \texttt{==} \texttt{!=} は候補が 4 つあるが戻り値がすべて \ty{bool} なので
曖昧にはならない（曖昧判定は\emph{戻り値型が割れたとき}だけ行う）。

\section{文}

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
文 & 意味 \\
\midrule
\texttt{var x = e;} & 変数宣言 \\
\texttt{var x = new C(args);} & アクター生成つき宣言 \\
\texttt{x = e;} & 代入 \\
\texttt{f(args);} \quad \texttt{call f(args);} & 組込み関数の呼び出し \\
\texttt{send t.m(args);} & 非同期送信。返信を待たない \\
\texttt{send self.m(args);} & 自分自身への非同期送信 \\
\texttt{send sender.m(args);} & 送信元への非同期送信 \\
\texttt{send! t.m(args);} & 検査を緩めた送信 \\
\texttt{if (e) s} \quad \texttt{if (e) s else s} & 条件分岐（括弧が要る） \\
\texttt{while e do s} & 繰り返し（括弧は要らない） \\
\texttt{\{ s ... \}} & ブロック \\
\texttt{become C(args);} & 振る舞いの置換（効果 \eff{mut}） \\
\texttt{select \{ ... \}} & メッセージの選択受信 \\
\bottomrule
\end{tabular}
\end{center}

\begin{quote}\small
\texttt{now self.m()} と \texttt{now sender.m()} は\textbf{文法上書けない}。
自分への \texttt{now} は自己デッドロックになる（自分は今そのメソッドを
処理中なので、返信を作る主体がいない）ので、書けないことがそのまま
安全側に働いている。幾何計算などを別に切り出したいときは、
別アクターに置いて \texttt{now kin.solve(...)} と呼ぶ。
\end{quote}

\begin{quote}\small
\texttt{var x : T = e;} という型注釈つきの変数宣言は\textbf{まだ無い}。
仕様案にはあるが未実装である。
\end{quote}

\section{アクターと通信}

\subsection{三つの送信}

\begin{center}
\begin{tabular}{@{}llll@{}}
\toprule
 & 待つか & 式か文か & 呼ばれる側の効果を負うか \\
\midrule
\texttt{send a.m(x);}      & 待たない     & 文 & 負わない \\
\texttt{now a.m(x)}        & 返信まで待つ & 式（結果は宣言／推論された型） & \textbf{負う} \\
\texttt{future a.m(x)}     & 待たない     & 式（\ty{future\ T}） & 負わない \\
\bottomrule
\end{tabular}
\end{center}

「待つ側だけが呼ばれる側の効果を負う」というのが効果伝播の規律である
（\S\ref{sec:effects}）。

\subsection{\texttt{reply}}

メソッドは値を「返す」のではなく \texttt{reply(v)} で呼び出し側の future を
解決する。型システムはメソッドごとに戻り値型を持ち、本体のすべての
\texttt{reply} と、すべての \texttt{now} / \texttt{future} 送信地点が
この型を共有する。

\begin{itemize}
\item \texttt{reply} は\textbf{高々一度}。2 度目は待ち手がすでに 1 度目の値を
  受け取ったあとに来るので黙って捨てられる。これは型エラーにしてある。
\item 戻り値型を \ty{unit} 以外で\emph{宣言}した場合は、
  \textbf{全実行パスでちょうど一度}になることが検査される。
  \texttt{while} の本体は 0 回実行されうるので、保守的に「reply しない
  パスがある」と判定される。
\item \texttt{reply} がまったく無いメソッドは戻り値 \ty{unit} と扱われる。
  \texttt{send} で呼ぶ「通知」型のメソッドがこれにあたる。
\end{itemize}

\begin{lstlisting}
method m(k) : int { reply(k); reply(k + 1); }                     // 型エラー
method m(k) : int { if (k > 0) { reply(1); } else { reply(2); } } // OK
\end{lstlisting}

\subsection{\texttt{select}}

\begin{lstlisting}
select {
  case job(k) -> { reply("done:" ++ k); }
  timeout 500 -> { print("timed out"); }
}
\end{lstlisting}

\texttt{case m(x1, ..., xn)} は同名メソッドの署名に照合される。
引数の個数と型が合わないと型エラーになる。
\texttt{timeout} の単位はミリ秒で、省略できる。

\textbf{case 本体の \texttt{reply} は、囲むメソッドではなく
「選択されたメッセージ」への返信である。}
処理系が case の実行前に返信先を選択されたメッセージへ切り替えるためで、
上の例の \texttt{reply} は \texttt{job} への返信になる。したがって
\texttt{select} を含むメソッド自身は \ty{unit} でよい。
一方 \texttt{timeout} 本体は囲むメソッドの返信先のまま実行される。

\begin{quote}\small
\texttt{select} は\emph{まだ処理されていない}メッセージを mailbox から探す。
通常のメソッド dispatch が先に同名メッセージを取ってしまうと
case には残らないので、\texttt{select} で待つ名前は直接呼ばせない設計に
するのが安全である（\S\ref{sec:g4} の実行結果を参照）。
\end{quote}

\section{期限付きの待ち}
\label{sec:deadline}

\subsection{なぜ必要か}

\texttt{now} や \texttt{await} を期限なしで書くと、返信が来なければ
永久に待つ。アクターは 1 台 1 スレッドで、待ちは条件変数でブロックするので、
待っている間そのアクターは他のメッセージを一切処理できない。石になる。

\begin{lstlisting}
now t.m(a) timeout <ミリ秒> else <式>
await f    timeout <ミリ秒> else <式>
\end{lstlisting}

期限内に返信が来ればその値、来なければ \texttt{else} 節を評価した値になる。

\subsection{規則}

\begin{itemize}
\item \texttt{else} 節は\textbf{本体と同じ型}でなければならない。
  期限切れでも式全体の型は変わらないためである。
  違うと \texttt{now: the else branch has type string but the call returns int}。
\item 期限は\textbf{正}でなければならない（\texttt{timeout must be positive}）。
\item 期限なしの \texttt{now} / \texttt{await} は既定では\textbf{警告}で、
  \texttt{AIOS\_STRICT\_DEADLINE=1} で\textbf{エラー}になる。
\item \texttt{reply} 回数の上界は、本体と \texttt{else} の
  \emph{どちらか一方}が走るとみなして \texttt{max} を取る（和ではない）。
\item 拒否された future（\texttt{reject}）は期限切れとは区別され、例外になる。
\end{itemize}

実装では OCaml の \texttt{Condition} に時限待ちが無いので、1\,ms 刻みの
ポーリングで期限を測っている。

\subsection{型健全性との関係}
\label{sec:soundness}

期限を必須にすると、待ちは「残り時間を減らす簡約」になり、時間が尽きれば
\texttt{else} 節へ簡約される。その結果\textbf{進行定理が二択になり}
（終状態か、簡約できるか）、ブロックの枝が消えて\textbf{デッドロック自由}が
系として言える。第 1 版の報告書が「一般には言えない」と明記した性質である。

ただしこれは\emph{デッドロックが有限時間の失敗に変換される}ということであって、
失敗が消えるわけではない。互いに \texttt{now} で待ち合う二者は両方が期限切れになる。
詰まらないが正しくもない。停止性も依然として言えない。

詳細は \texttt{docs/aipl\_soundness2\_ja.pdf}（型健全性・型安全性の第 2 版）にある。

\subsection{これで何が禁止できるか}

\begin{lstlisting}
class Controller {
  method step(s) : string !{io, time} {
    var r = now planner.plan(s) timeout 100 else "";   // plan は !{ai, net}
    reply(r);
  }
}
\end{lstlisting}

\begin{term}
[Type error] method Controller.step declares {io, time}
  but its body has {ai, net, io, time} (missing {ai, net})
\end{term}

「実時間で動くアクターが、機外のエージェントを同期で呼ぶ」ことが
効果検査だけで禁止される。これは設計判断として述べていたものが、
型システムの上で機械的に効くようになったということである。

\begin{quote}\small
\textbf{既知の穴。} \texttt{now} を \texttt{future} と \texttt{await} に

伝播の辺を張らず、\texttt{await} では伝播させていないためである。
再現は \texttt{docs/samples/}\allowbreak\texttt{soundness2\_effect\_gap.abcl}
にある。
修正方針（\ty{future} の型に効果を載せる）は第 2 版の報告書に書いてある。
\end{quote}

REPL の主なコマンドは
\texttt{load} / \texttt{compile} / \texttt{list} / \texttt{send} /
\texttt{ast} / \texttt{pprint} / \texttt{script} / \texttt{exit} である。

\section{型と実行値の差分テスト}

型検査が付けた戻り値型と、実行時に実際に \texttt{reply} された値の型を
突き合わせるハーネスがある。

\begin{term}
python3 scripts/type_runtime_diff.py abclc/*.abcl docs/samples/guide/*.abcl
\end{term}

処理系側は \texttt{AIOS\_TYPE\_TRACE=1} のとき \texttt{reply} のたびに
\texttt{[rtype] Class\#method = tag} を出す。この仕組みで、整数演算が
\ty{float} を返していた不整合（$\vdash e : \ty{int}$ なのに
$e \Downarrow$ \texttt{VFloat}）が実際に見つかった。
わざと食い違う負例には
\texttt{// TYPE\_RUNTIME\_DIFF: expect-mismatch} と書いておけば既知として扱われる。

\textbf{型を変更したら必ず回すこと。} これが preservation の破れを見つける常設装置である。

\section{文法の要約}

\begin{term}
program    ::= decl+

decl       ::= "class" ID "{" field* method+ "}"
             | "var" ID "=" expr ";"
             | "var" ID "=" "new" ID "(" args ")" ";"
             | "send"  target "." ID "(" args ")" ";"
             | "send!" target "." ID "(" args ")" ";"
             | ID "(" args ")" ";"

field      ::= "var"   ID "=" expr ";"
             | "float" ID "=" expr ";"

method     ::= "method" ID "(" params ")" ret? eff? "{" stmt+ "}"
ret        ::= ":" ("int"|"float"|"string"|"bool"|"unit"|"any"|ClassName)
eff        ::= "!" "{" (ID ("," ID)*)? "}"

target     ::= ID
             | "remote" "(" STRING "," STRING ")"

stmt       ::= ID "=" expr ";"
             | "var" ID "=" expr ";"
             | "var" ID "=" "new" ID "(" args ")" ";"
             | ID "(" args ")" ";"
             | "call" ID "(" args ")" ";"
             | "send"  ("self"|"sender"|target) "." ID "(" args ")" ";"
             | "send!" target "." ID "(" args ")" ";"
             | "if" "(" expr ")" stmt ("else" stmt)?
             | "while" expr "do" stmt
             | "{" stmt* "}"
             | "become" ID "(" args ")" ";"
             | "select" "{" case* timeout_case? "}"

case         ::= "case" ID "(" ids? ")" "->" "{" stmt+ "}"
timeout_case ::= "timeout" INT "->" "{" stmt+ "}"

expr       ::= INT | FLOAT | STRING | "true" | "false" | ID
             | "-" expr
             | expr ("=="|"!="|">"|"<"|">="|"<="|"++"|"+"|"-"|"*"|"/") expr
             | "new" ID "(" args ")"
             | "now" target "." ID "(" args ")" ("timeout" INT "else" expr)?
             | "future" target "." ID "(" args ")"
             | "await" expr ("timeout" INT "else" expr)?
             | ID "(" args ")"
             | "(" expr ")"
\end{term}

演算子の優先順位は弱い順に、
\texttt{==} \texttt{!=} $\;<\;$
\texttt{>} \texttt{<} \texttt{>=} \texttt{<=} $\;<\;$
\texttt{++} $\;<\;$
\texttt{+} \texttt{-} $\;<\;$
\texttt{*} \texttt{/} $\;<\;$ 単項マイナス。二項演算子は\textbf{すべて左結合}である（等値も含む）---- \texttt{1 == 2 == false} は \texttt{((1 == 2) == false)} と読まれて \texttt{true} になる。単項マイナスは前置なので重ねられる（\texttt{- - 3} は \texttt{3}）。

\section{処理系の環境変数}

型検査と実行の挙動を変えるものが 6 つある。いずれも \texttt{1} を設定して有効にする。
既定は「有効にしない」側である。

\begin{center}
\small
\begin{tabular}{@{}lp{9.4cm}@{}}
\toprule
変数 & 効果 \\
\midrule
\texttt{AIOS\_STRICT\_DEADLINE} &
  期限のない \texttt{now} / \texttt{await} を\textbf{エラー}にする。
  既定では警告にとどまる。型健全性の定理が成立する範囲
  （AIPL$^{-2}$）に留まりたい場合はこれを立てる \\
\texttt{AIOS\_LAX\_OVERLOAD} &
  オーバーロードの曖昧さを、エラーではなく
  「警告して既定候補を選ぶ」\textbf{従来動作}に戻す。
  既定は厳格（エラー）である \\
\texttt{AIOS\_LAX\_EXPOSE} &
  公開アクター（\S\ref{sec:expose}）の注釈漏れを警告に落とす。
  既定はエラー \\
\texttt{AIOS\_TYPE\_TRACE} &
  \texttt{reply} のたびに \texttt{[rtype] Class\#method = tag} を出す。
  静的に付いた戻り値型と実際に返った値の型を突き合わせる
  差分テスト（\texttt{scripts/type\_runtime\_diff.py}）が使う \\
\texttt{AIOS\_QUIET} &
  型検査器と REPL の情報メッセージを抑止する \\
\texttt{AIOS\_MODEL\_PROVIDER} &
  \texttt{ai\_call} が使うモデル事業者。既定は \texttt{gemini} \\
\bottomrule
\end{tabular}
\end{center}

\begin{lstlisting}
AIOS_STRICT_DEADLINE=1 ./src/abclrepl_thread -q -f run.repl
\end{lstlisting}

\section{よくある落とし穴}

\begin{itemize}
\item \textbf{\texttt{now} は式である。} \texttt{now x.m();} は構文エラー。
  必ず \texttt{var r = now x.m() timeout 100 else 0;} のように受ける。
\item \textbf{\texttt{send} の宛先は変数}であってクラス名ではない。
\item \textbf{\texttt{now self.m()} は書けない}（自己デッドロックになるため
  文法で禁止されている）。計算を切り出したいなら別アクターへ。
\item \textbf{\texttt{var x = 0;} に後からアクターを代入できない}
  （\ty{int} に推論されている）。最初から \texttt{var x = new Foo();} で作る。
\item \textbf{文字列連結は \texttt{++}}。\texttt{+} は数値専用。
\item \textbf{フィールドはメソッドより前}に書く。
\item \textbf{待ちには期限を書く}。書かないと警告が出るし、
  \texttt{AIOS\_STRICT\_DEADLINE=1} では通らない。
\item \textbf{効果は申告すると検査される}（gradual）。申告しなければ
  何も言われない。書けば実体との差を突いてくる。
\end{itemize}

\section{現状の限界}

\begin{itemize}
\item \texttt{future} + \texttt{await} に分けて書くと効果伝播を逃れる
  （\S\ref{sec:effects} の「既知の穴」）。修正には
  \ty{future} の型に効果を載せる必要がある。
\item 型注釈つきの変数宣言 \texttt{var x : T = e;} が無い。
\item \texttt{sender} は \ty{any} で、\texttt{send sender.m(...)} は
  メソッドの存在も型も検査されない。
\item \texttt{send t.no\_such\_method()} が通る場合がある。
\item リモート送信先（\texttt{remote(...)}）の戻り値は \ty{any} のまま。
  対向ノードのインタフェース記述を読み込む仕組みが無い。
\item アクター型が単一化で区別されない
  （\texttt{actor(A)} と \texttt{actor(B)} が単一化に成功する）。
\item \texttt{become C(...)} はコンストラクタの引数しか検査せず、
  置換後のインタフェースが元と一致するかを見ていない。
\item メソッドの引数は単相で、多相なメソッドは書けない。
\item \ty{int} と \ty{float} の間に暗黙変換が無く、
  両辺が未束縛の \texttt{a + b} は注釈が必要。
\item 配列リテラル \texttt{[...]} は無い。
  \texttt{array\_empty} と \texttt{array\_push} で作る。
\item 停止性は保証されない。デッドロック自由は
  「期限付きの待ちだけを使う」場合に限る。
\end{itemize}

\section{前版からの変更点}
\label{sec:migrate}

前版（対象コミット \texttt{04892cf}）以降の言語の変化は次の 3 点である。
いずれも既存のプログラムを壊さない（既定では警告どまり）。

\begin{center}
\small
\begin{tabular}{@{}lp{7.4cm}l@{}}
\toprule
 & 内容 & 影響 \\
\midrule
効果注釈 & \texttt{method m(x) : T !\{ai, net\}} を書けるようになった。
  省略すれば推論のみ & 追加のみ \\
期限付きの待ち & \texttt{now ... timeout $n$ else $e$} /
  \texttt{await ... timeout $n$ else $e$}。期限なしは警告
  （\texttt{AIOS\_STRICT\_DEADLINE=1} でエラー） & 追加＋警告 \\
式の文法の補完 & \texttt{==} \texttt{!=} / 単項マイナス \texttt{-e} /
  \texttt{true} \texttt{false} が書けるようになった & 追加のみ \\
\bottomrule
\end{tabular}
\end{center}

さらに前版の時点で導入済みだったもの（それ以前から移行が要る点）は、
\texttt{+} から \texttt{++} への文字列連結の分離、
曖昧なオーバーロードのエラー化、公開アクターへの注釈必須化、
仮引数のシグネチャへの結線、二重 \texttt{reply} の禁止である。
背景と測定結果は \texttt{docs/aipl\_reply\_inference\_ja.pdf} にある。
